Jev Observer 0.2.0 adds explicit provider configuration for TypeSafe, OpenRouter and a local Laya System One server. It improves credential replacement, history queries and release verification while keeping live history encrypted and the dashboard local.

## Provider connections

OpenRouter uses the System One endpoint at `https://openrouter.ai/api/v1/systemone`. Local Laya uses its loopback System One endpoint with provider authentication disabled explicitly; dashboard authentication still protects local history and forwarding. See the [connection guide](https://github.com/LimePencil/jev-observer/blob/main/docs/connection.md) for complete commands and SDK setup.

Provider-reported usage and cost remain distinct from user-configured estimates. The connection panel shows the selected provider, endpoint and authentication mode. Invalid or incomplete captures remain visible instead of contributing valid answers to distributions.

OpenRouter and Laya Score values that differ from their displayed weighted probabilities retain their original values with an explicit consistency warning. Structural errors, missing answers and invalid distributions remain invalid.

## Explore retained history

Request and group pagination, server-side group search, date ranges and shareable local filters make older history accessible from the dashboard. Definition comparisons include distributions, review counts, usage and sample sizes; unmatched histories are not presented as a controlled accuracy comparison. Timelines cover the selected range and position activity by its actual time.

## Reliability and verification

- Credential replacement preserves the active credential and saved approval when its storage update fails.
- Unsupported plaintext and encrypted database schemas are rejected before changing their contents. Failed response transfers appear in the Failures view even when the upstream originally returned a successful HTTP status.
- Dashboard grouping uses the request index, with regression checks for large retained histories.
- Browser integration checks exercise the packaged dashboard against the real backend, including review labels, imports and exports.
- Release checks exercise an upgrade from the published 0.1.0 executable, encrypted history and backup restoration, and rejection of unsupported future database schemas.
- Manual release verification includes the final six-platform archive and checksum checks. Missing release notes or inconsistent versions fail before native builds, and release candidates are marked as prereleases without replacing the latest stable release.

## Upgrade

Stop Observer cleanly, then back up the database and any remaining SQLite sidecar files before replacing the executable. Keep the same saved `JEV_OBSERVER_DB_KEY`; losing it makes encrypted history unreadable. Rerun the installer with `--version 0.2.0` on Unix or `-Version 0.2.0` in PowerShell. See [installation](https://github.com/LimePencil/jev-observer/blob/main/docs/installation.md) for commands and supported platforms.

Restore a stopped-process backup to recover an earlier history. Session-only provider keys need registration again after restart. Operating-system credential storage still depends on the local credential store being available and unlocked.

Version 0.2.0 can load an existing 0.1.0 saved credential. After rotating a saved key in 0.2.0, downgrading to 0.1.0 requires registering the provider key again: the older executable cannot locate the new credential-store entry. Restoring the database alone does not restore a removed credential-store entry. The automated upgrade check verifies a synthetic database approval hash; it does not exercise native credential-store persistence.

macOS and Windows executables remain unsigned. SHA-256 checksums verify downloaded bytes, not publisher identity. Compatibility and performance claims apply only to the builds, providers and workloads recorded in the [validation evidence](https://github.com/LimePencil/jev-observer/tree/main/reports/validation/next-release).

## Validation

Local source checks passed formatting, Clippy with warnings denied, 105 Rust tests and six release-metadata regression tests. One CSV timing probe remains intentionally ignored by the ordinary Rust test command. Publication still requires all six native release jobs and the aggregate archive checks to pass; local results do not replace those platform checks.
