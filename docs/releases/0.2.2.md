Jev Observer 0.2.2 fixes misleading token totals in the dashboard when requests report incomplete usage.

## Token usage coverage

- Track how many requests report input tokens and output tokens separately within the selected dashboard window and filters.
- Mark token totals as partial when some requests omit usage, and show unknown usage when no tokens are reported. Reported zero-token counts remain known values.
- Show separate input and output coverage so values reported by different requests cannot appear to cover every request. For example, one request reporting only 100 input tokens and another reporting only 20 output tokens previously appeared as an unqualified total of 120 tokens.

The fix reads existing history without a database schema change. It does not change captured token values, provider forwarding or model compatibility.

## Upgrade

Stop Observer cleanly and back up the database and any SQLite sidecar files before replacing the executable. Keep the same saved `JEV_OBSERVER_DB_KEY`. Rerun the Unix installer with `--version 0.2.2` or the PowerShell installer with `-Version 0.2.2`. See the [installation guide](https://github.com/LimePencil/jev-observer/blob/v0.2.2/docs/installation.md).

Credential storage and downgrade limitations from 0.2.0 still apply. macOS and Windows executables remain unsigned.

## Validation

Regression coverage exercises complete, partial and unknown usage, including independently missing input and output counts and reported zero tokens. The release workflow requires native Rust checks, browser and packaged-backend tests, upgrade checks and SDK checks on Linux, macOS and Windows for x86_64 and ARM64. Publication follows verification of all six archives and the aggregate SHA-256 manifest.
