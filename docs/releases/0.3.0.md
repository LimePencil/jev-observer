# Jev Observer 0.3.0

0.3.0 brings the October service improvements to the published executable: lower capture allocation and memory use, faster history queries and pagination, more reliable transport accounting, stricter import privacy/resource limits, and dashboard navigation and review fixes.

## Changes

- Bound automatic timeline edge probes to 512 oldest/newest parents per missing bound. Dense scopes avoid a full min/max scan; sparse or ineligible edges retain the exact aggregate fallback. Explicit bounds remain unchanged.
- Optimize catalog lookups, date selections, history pagination, retention and review updates. Dashboard reads allow up to 45 seconds and show slow-query feedback after five seconds.
- Reduce dense-capture allocations, preserve HTTP framing and deadlines, account for interrupted transfers, and redact credentials from errors and imported metadata.
- Preserve pending reviews across drawer close/reopen and stale responses; fix filter/focus and pagination recovery.
- Update compatible dependencies, license notices and CI cache reuse.

The [October validation archive](../../reports/validation/october-2026/README.md) records the earlier 58 improvement PRs and their exact evidence. Its historical results apply to their named source versions; interrupted endurance runs remain partial.

## Compatibility and known limits

No new database schema or credential identity is introduced by this release. Stop Observer and preserve the encrypted workspace, database key and previous executable before upgrading; see [installation and rollback](../installation.md#history-backups-and-downgrades).

Broad queries at the default one-million-record cap remain workload-dependent; the 45-second dashboard deadline is not a latency guarantee. [#102](https://github.com/LimePencil/jev-observer/issues/102) tracks the remaining performance work.

The Linux credential dependency chain still uses zbus 5. The latest compatible keyring 4.2.0, secret-service 5.2.0 and zbus-secret-service-keyring-store 1.0.1 do not yet support a lockfile-only zbus 6 migration. [#62](https://github.com/LimePencil/jev-observer/issues/62) remains an upstream-dependent maintenance follow-up; its advisories do not identify a concrete vulnerability. Native OS credential-store persistence is not covered by the synthetic upgrade fixture.

## Release verification

Publication requires the tag workflow to pass native Rust, UI, packaged-browser, SDK, upgrade and archive verification on Linux x64/ARM64, macOS Intel/ARM64, and Windows x64/ARM64. Downloads include six platform archives and SHA256SUMS. macOS and Windows binaries remain unsigned.
