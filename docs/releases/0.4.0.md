# Jev Observer 0.4.0

0.4.0 adds native Decisions and multimodal inspection, expands the source-reviewed model catalog, and improves privacy, history maintenance and dashboard interaction. It also separates the backend and frontend into smaller modules while preserving their ownership and transaction boundaries.

## Models and captured data

- Select the wire format with `--protocol` and the validator with `--model-profile`, independently of the credential and billing `--provider`. System One remains the default. OpenAI Decisions uses `/v1/decisions`; Cloudflare System One retains its result wrapper on the wire.
- Native Decisions keeps ordered questions, optional names, refusals and typed Choice values. Boolean `true` and string `"true"` remain distinct in observations, probabilities and distributions. Score rubrics retain their original order and labels.
- TypeSafe and H2O profiles support Box geometry, confidence and documented presence fields. Box observations remain individually reviewable and do not produce scalar means or histograms. H2O's no-localization result does not establish that a target is absent.
- The catalog contains 54 entries with per-entry review dates and pinned primary sources. New entries cover OneJev, the two distinct Omni formats, Clef runtimes, Liquid D1, Microsoft Decision, H2O Lightning and other documented decision families. Saved OmniJev and Jev-Omni results have explicit offline adapters; unsupported mappings are rejected rather than guessed. Abstention mass remains visible and invalid for complete-distribution statistics.
- Captured copies can decode one bounded gzip member or zstd frame and supported image multipart requests after forwarding. Wire bytes are unchanged. Unsupported or oversized inspection data produces a minimal incomplete record with a static reason. Input capture remains opt-in; original JSON reaches secret discovery before known input fields are removed. Decoding limits are not a total process-memory cap.

See [models and source scope](../models.md), [connection examples](../connection.md) and [captured transport limits](../capture-decoding.md). Catalog research and synthetic fixtures establish the documented inspection contract, not live provider availability, model quality or universal compatibility.

## History, privacy and dashboard

- Credential redaction detects object-key and semantic-identifier collisions, preserves generated capture identities, and fails closed when privacy filtering would repair invalid validation metadata. External import identities that change under redaction are rejected atomically. Known input paths are omitted before their field names can be renamed by redaction.
- Filtered exports select integer identities once and fetch bounded pages in fresh read transactions. Dashboard temporary payload sorting stays in memory. Retention and Delete all history use bounded delete statements inside one transaction, preserving atomic visibility and rollback. The statement row bound is not a universal memory cap.
- Version counts reuse transaction-local results. Query results retain their request scope, pagination and definition identities. The experimental family-selection optimization with measured regressions is excluded.
- Pending imports and deletion retain status when their drawers close. Review feedback follows the current saved label. Request navigation survives a concurrent group search; timelines resize to their rendered width, and inspection timestamps show full dates and offsets. Large JSON disclosures remain lazy.
- Workspace tokens use the complete database filename plus `.token`, and Unix saved-credential identities preserve native path bytes. Basic authentication and localhost case handling retain their existing authorization and cross-origin guards. Updated TLS trust and Vite dependencies address reviewed advisories; the Vite advisories concern development tooling, with no demonstrated embedded production exposure.

## Upgrade and rollback

Stop Observer and preserve a complete pre-upgrade workspace copy, its database key, current and legacy token files, required provider credentials and the previous executable. On first upgrade from a legacy `*.access-token` workspace, sign in again with the fresh token printed by 0.4.0 and update clients that use workspace authentication. The old token file is left untouched. Saved-credential path changes can require re-registration for Unix paths containing invalid UTF-8 bytes.

**New Box data is not supported by older readers.** Earlier versions assume a valid non-Choice answer is numeric, so dashboard or group queries can fail on a history containing valid Box records even though the database schema is unchanged. Older versions also lack native Decisions and the new protocol/profile flags. Do not assume that swapping the executable or exporting new records as JSONL makes those records backward compatible.

For rollback, keep the upgraded workspace separately and restore the stopped pre-upgrade snapshot for the earlier executable. It will not contain observations collected after that snapshot. Preserve the upgraded copy for a later return to 0.4.0. Legacy upgrade-test success does not extend to every new answer kind. See [installation and downgrade details](../installation.md#history-backups-and-downgrades) for token and operating-system credential limitations.

## Release verification

Publication requires native Rust tests, formatting, Clippy, the production dashboard/browser checks, packaged-backend checks, installer and legacy upgrade checks on Linux x64/ARM64, macOS Intel/ARM64 and Windows x64/ARM64. The legacy Python 0.7.1 and JavaScript 0.6.0 SDK loopback fixture remains separate from the current Python 0.7.5 and JavaScript 0.7.0 compression/multipart fixture. The current fixture runs on Linux; it does not establish current-SDK behavior on every operating system. No release fixture requires paid inference or a real provider call.

The tag workflow verifies all six native archives and their aggregate `SHA256SUMS` before publication. macOS and Windows binaries remain unsigned. Source-level compatibility, synthetic runtime checks and actual release artifacts are distinct evidence; the release workflow records the final native results.
